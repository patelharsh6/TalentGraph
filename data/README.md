# TalentGraph data

This folder holds the skill taxonomy, the synthetic resume and job corpora, and the gold sets used
to build and evaluate Phases 2–4. Everything here is generated by scripts in `scripts/` from
fixed seeds, and two runs produce byte-identical files (exit criterion 1-I).

## What is committed and what isn't

| Path | In git? | Why |
|---|---|---|
| `taxonomy/*.csv`, `taxonomy/*.yaml`, `taxonomy/ATTRIBUTION.md` | yes | Small text; needed by tests and seeding |
| `taxonomy/wikidata_aliases.csv` | yes | Snapshot of a live source, so builds are reproducible offline |
| `taxonomy/raw/download.py` | yes | Pinned O\*NET downloader |
| `taxonomy/raw/onet/` | **no** | Downloaded source tables (~3.7 MB); rerun the downloader |
| `profiles/*.gt.json`, `jobs/*`, `eval/*` | yes | JSON/CSV ground truth; unit tests read them |
| `resumes/` | **no** | ~15 MB of rendered PDF/DOCX/TXT; regenerate it. An 18-resume sample (3 per template) is in `tests/fixtures/resumes/` |
| `.checkpoints/` | **no** | Generator scratch state |

## Regenerate everything

```bash
uv run python data/taxonomy/raw/download.py       # once: O*NET 31.0 tables (hash-checked)
uv run python scripts/regenerate_data.py          # all steps below, in order
uv run python scripts/regenerate_data.py --check  # run twice and compare SHA-256 (1-I)
```

The individual steps are listed below. Each one also accepts `--stats`, which prints statistics
and exits non-zero if its exit criterion fails.

| Step | Script | Output |
|---|---|---|
| 1 | `scripts/build_taxonomy.py` | `taxonomy/skills.csv`, `taxonomy/aliases.csv` |
| 2 | `scripts/gen_profiles.py --count 560` | `profiles/candidate_NNNN.gt.json` |
| 3 | `scripts/render_resumes.py` | `resumes/{train,val,test}/`, `tests/fixtures/resumes/` |
| 4 | `scripts/gen_jobs.py --count 120` | `jobs/job_NNN.txt` + `.gt.json` |
| 5 | `scripts/build_normalization_gold.py` | `eval/normalization_gold.csv` |
| 6 | `scripts/label_matches.py` | `eval/match_gold.csv`, `eval/human_labeling.csv` |

To load the taxonomy into Postgres and Chroma (with the compose stack up), run the seeder inside
the api container. torch can't load natively on some Windows machines.

```bash
docker compose run --rm --no-deps -v "$PWD/scripts:/app/scripts:ro" \
  -v "$PWD/data/taxonomy:/app/data/taxonomy:ro" api python scripts/seed.py --taxonomy --stats
```

`scripts/fetch_wikidata_aliases.py` refreshes the Wikidata snapshot. It needs network access and
is not part of `regenerate_data.py`.

## Statistics (2026-10-03)

### Taxonomy (`scripts/seed.py --stats`)

- **9,642 skills** in 4 levels:

  | Level | Count | Notes |
  |---|---|---|
  | 0 (domains) | 4 | technical, business, soft skills, domain knowledge |
  | 1 (categories) | 38 | |
  | 2 (subcategories) | 205 | |
  | 3 (skills) | 9,395 | |

  There are no orphans and no cycles. Sources: about 780 curated skills, about 8,640 O\*NET
  software products (another ~120 products were merged into curated skills as aliases), and the
  O\*NET knowledge and skill elements.
- **15,122 aliases**, unique after normalization:

  | Source | Count |
  |---|---|
  | onet | ~8,700 |
  | variant | ~4,400 |
  | curated | ~1,600 |
  | wikidata | ~370 |

  Aliases that need context (`go`, `r`, `c`, `excel`, `word`, `pm`, `cv`, plain-word product
  names) are flagged `ambiguous=true`.
- **161 implication rules** and **310 relation edges**. One duplicate edge collapses on its primary
  key, so the database holds 309.
- **Version:** `taxonomy_version` is the first 16 hex characters of a SHA-256 over the four
  taxonomy files, with line endings normalized.

### Profiles and resumes (`scripts/render_resumes.py --stats`)

- 560 ground-truth profiles (`ParsedResume` plus gold canonical slugs), 11 industries
  (software, data, finance, healthcare, marketing, design, manufacturing, education, sales,
  legal, operations) and 5 seniority levels.
- About 5.5% of profiles contain one made-up emerging skill. It is stored with
  `canonical_slug: null, emerging: true`.
- One rendered resume per profile:
  - **Formats:** PDF 235 (42.0%), DOCX 232 (41.4%), TXT 93 (16.6%).
  - **Templates:** single_column, two_column, sidebar, table_based, creative (PDF/DOCX) and
    minimal_txt (TXT), about 93 each.
- **Noise:** ~1% character typos in free text and skill names, mixed date formats, synonym section
  headers, 10% of resumes drop one optional section (56) and 30% shuffle section order (164).
  Dropped sections are removed from that resume's `.gt.json` as well, and `meta.noise` records
  what was applied.
- **Split:** 70/15/15 train/val/test, stratified by (industry, template): 384/88/88.

### Jobs (`scripts/gen_jobs.py --stats`)

- 120 job descriptions (`job_NNN.txt`) with `JobRequirements` ground truth (`.gt.json`:
  canonical skill slugs, required/importance, min_years).
- Role families: engineering, data, cloud, product, design, finance, marketing, healthcare and
  manufacturing. Five seniority levels.

### Normalization gold (`scripts/build_normalization_gold.py --stats`)

- 1,200 rows: `raw, context, expected_slug, case_type, is_hard_case, split`.
- `expected_slug` is a slug, `NEW` (not in the taxonomy), or several slugs joined by `|` for a
  multi-skill string.
- **305 hard cases (25.4%):**

  | Case type | Count |
  |---|---|
  | typo | 160 |
  | version | 40 |
  | ambiguous with context | 30 |
  | unknown/`NEW` | 30 |
  | abbreviation | 25 |
  | multi-skill | 20 |

- **895 easy rows:** every skill string used in the profiles and JDs, plus a seeded sample of
  non-ambiguous aliases.
- **Split:** 50/50 val/test, stratified by case type. Every expected slug exists in the taxonomy.

### Match gold (`scripts/label_matches.py --stats`)

- 2,400 pairs: 120 jobs × 20 candidates, split 70/15/15 by job.
- **Grades:**

  | Grade | Pairs | Share |
  |---|---|---|
  | 0 | 622 | 25.9% |
  | 1 | 615 | 25.6% |
  | 2 | 629 | 26.2% |
  | 3 | 294 | 12.2% |
  | 4 | 240 | 10.0% |

  No grade exceeds 40%.
- Grades come from a **deterministic labeler** that applies `eval/match_rubric.md` to the ground
  truth, not from an LLM judge (ADR-0002). Because it scores skill overlap, it is circular for an
  overlap-based matcher. M3 must be re-validated with the LLM judge or with human labels before
  Phase 4 sign-off.
- `eval/human_labeling.csv` holds 240 pairs with an **empty** `human_grade` column for human
  double-labeling. `label_matches.py --stats` reports quadratic-weighted Cohen's κ once it is
  filled in. Status: **pending**.

## Known limitations

- **Synthetic text:** all resume and JD text is template-generated (no LLM; ADR-0002). It is
  cleaner and more repetitive than real resumes, so parsing metrics may be optimistic.
- **Taxonomy skew:** the level-3 taxonomy is dominated by O\*NET software products. ESCO is not
  used (ADR-0001), so business and soft-skill coverage is thinner.
- **OCR:** image-only and scanned PDFs are out of scope for v1 (plan D7).
- **Language:** English only.
- **Privacy:** all PII is synthetic (Faker). No real resumes are stored here.
